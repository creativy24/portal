Tentang AutoLogin Manager

Apa itu AutoLogin?
AutoLogin Manager adalah sistem manajemen autentikasi otomatis untuk perangkat OpenWrt. Sistem ini mendeteksi captive portal pada setiap interface jaringan, mengklasifikasikan tipe portal, dan menyimpan profil login untuk autentikasi berulang tanpa intervensi manual. Setelah profil disimpan, sistem akan secara otomatis menjaga koneksi tetap hidup (auto-reconnect) dan memulihkan koneksi jika terjadi pemblokiran (anti-blokir).

Fitur-Fitur Utama:

Deteksi Captive Portal
Sistem secara otomatis mendeteksi captive portal pada setiap interface yang aktif. Berbagai jenis portal didukung, termasuk wifi.id (Klasik & Next.js), WMS (Wifi Corner), dan Hotspot MikroTik. Deteksi dilakukan dengan menganalisis URL redirect, meta refresh, dan HTML signature. Semua aturan deteksi disimpan di file portal.json sehingga mudah ditambahkan tanpa mengubah kode.

Spoofing MAC Address
Anda dapat mengganti MAC address interface dengan MAC virtual berbasis vendor (Android, Windows, macOS, Linux). Fitur ini berguna untuk menghindari pembatasan berbasis MAC atau untuk keperluan privasi. Sistem akan mengingat MAC asli dan dapat mengembalikannya (revert) kapan saja.

Multi-Metode Login
Mendukung berbagai metode login: Standar, Wico, Komunitas (Voucher Gift, Grosir & UMKM, Smart Bisnis, Kampus, Rumah Sakit, Internetku, SSO), dan ISP Operator (Boingo, iPass, Nusanet). Setiap metode memiliki transformasi username yang sesuai, dan semua konfigurasi dapat disesuaikan di file portal.json.

Manajemen Profil
Setiap konfigurasi interface disimpan sebagai profil yang dapat diedit, dinonaktifkan, atau dihapus. Profil mendukung pengaturan lanjutan seperti interval health check, cooldown, max retry, stabilisasi delay, dan notifikasi Telegram. Semua profil berjalan paralel tanpa saling mengganggu.

Auto-Reconnect
Setelah profil disimpan, daemon akan berjalan di latar belakang. Ia secara berkala memeriksa status koneksi menggunakan health check. Jika terdeteksi portal (PORTAL_DETECTED), sistem akan melakukan login ulang secara otomatis menggunakan kredensial yang tersimpan. Jika koneksi terputus (DISCONNECTED), sistem akan memverifikasi dan mencoba login kembali.

Anti-Blokir
Jika koneksi terus gagal atau diblokir oleh server, sistem akan menjalankan prosedur anti-blokir: merestart interface, merotasi hostname (untuk menghindari tracking), mendapatkan IP baru, memindai ulang portal, dan memperbarui profil dengan URL dan parameter sesi terbaru. Setelah itu, sistem mencoba login kembali secara otomatis.

Arsitektur Data-Driven
Semua aturan deteksi portal, handler script, normalisasi URL, session grid, dan pengaturan lainnya disimpan dalam satu file JSON (portal.json). Untuk menambahkan tipe portal baru, Anda cukup menambahkan satu blok aturan di file tersebut tanpa harus mengedit kode program. Ini membuat sistem sangat fleksibel dan mudah dikembangkan.

Cara Menggunakan (Alur Kerja):
1. Klik DAFTAR INTERFACE untuk memindai interface yang aktif. Sistem mendeteksi captive portal dan menampilkan tabel hasil scan.
2. Klik PILIH INTERFACE pada baris yang diinginkan. Formulir konfigurasi akan terbuka dengan field INTERFACE, PORTAL TYPE, dan MAC ADDRESS terisi otomatis.
3. (Wajib) Klik DETECT URL. Sistem akan merestart interface dan memindai ulang URL portal. URL yang muncul di field URL LOGIN sudah dilengkapi parameter sesi (gw_id, sessionid, dll.).
4. Isi Username dan Password. Jika muncul dropdown LOGIN METHOD (untuk WIFI_ID/WMS), pilih metode yang sesuai.
5. Klik LOGIN untuk menguji kredensial. Jika berhasil, tombol akan berubah menjadi LOGOUT.
6. Klik SIMPAN untuk menyimpan profil. Daemon akan mulai bekerja: auto-reconnect, anti-blokir, dan hotplug aktif.

Struktur Form Berdasarkan Tipe Portal:
- WIFI_ID & WMS: Menampilkan dropdown LOGIN METHOD (Standar, Komunitas, ISP) dan field Session Grid (GW_ID, WLAN, SESSIONID, IPC, CLIENT_MAC). WMS memiliki dropdown login method yang dikunci dan pemrosesan username khusus.
- HOTSPOT: Tidak menampilkan dropdown LOGIN METHOD maupun field Session Grid. Form hanya berisi INTERFACE, PORTAL TYPE, USERNAME, PASSWORD, PERANGKAT, MAC, dan URL LOGIN.

FAQ:
- Apakah sistem ini bisa berjalan otomatis setelah router restart? Ya, selama profil tersimpan dan interface aktif, daemon akan otomatis berjalan dan melakukan auto-reconnect.
- Berapa lama waktu yang dibutuhkan untuk auto-reconnect? Tergantung pengaturan Health Check Interval (default 30 detik). Sistem akan mencoba login ulang dalam siklus tersebut.
- Apa yang terjadi jika username/password salah? Setelah beberapa kali percobaan (sesuai Max Retry), sistem akan menghentikan percobaan dan menampilkan status PERMANENT_ERROR. Anda perlu mengedit profil dan memperbaiki kredensial.
- Apakah sistem bisa digunakan untuk lebih dari satu interface? Ya, setiap profil berjalan secara paralel dengan lock terpisah, tidak saling mengganggu.
- Bagaimana cara menambah dukungan untuk portal baru? Cukup tambahkan aturan deteksi dan handler script di file portal.json. Tidak perlu mengedit kode program.
